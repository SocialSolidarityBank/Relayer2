# 배포 안내

릴레이어는 API와 빌드된 화면을 한 프로세스로 제공한다. 기관 환경에서는 관리형
컨테이너, 기관 전용 호스트, 또는 조직이 승인한 실행 플랫폼 중 하나를 선택한다.
구체적인 호스트 주소·사용자 경로·자격 식별자는 이 문서에 기록하지 않는다.

## 기본 기동

```bash
node api/src/migrate.ts
node api/src/index.ts
```

개발에서는 Vite가 화면을 내고 `/api`를 프록시할 수 있다. 배포에서는 같은 출처에서
빌드된 `web/dist`를 제공하므로 별도 프록시가 필요하지 않다.

## 컨테이너 예시

```bash
docker build -t relayer:<release> .
docker run -p 8787:8787 --env-file .env relayer:<release>
```

`.env`는 저장소 밖에 두고 소유자만 읽게 한다. `docker run -e NAME=value`처럼 비밀을
명령행에 직접 넣지 않는다. 운영에서는 이미지 태그를 고정하고, 이미지 레지스트리와
실행 권한을 최소화한다.

## 환경 변수

필수 변수는 `DATABASE_URL`, `PII_ENC_KEY`, `SESSION_SECRET`이다. AI·음성·주소 라벨
등의 선택 변수와 의미는 `docs/secrets.md`를 참고한다. `PII_ENC_KEY`는 데이터베이스
백업과 다른 위치에 보관한다.

## 배포 전 확인

1. 운영 데이터가 아니라 합성 데이터로 마이그레이션과 화면 흐름을 먼저 확인한다.
2. 비밀 관리 시스템에서 필수 변수의 이름과 존재 여부만 확인한다.
3. 공개 HTTPS 엔드포인트와 역방향 프록시를 준비한다. 데이터베이스·관리 포트는
   공개하지 않는다.
4. `/health`, 로그인, 암호화된 기록 저장·조회를 확인한다.
5. 음성이나 AI를 켠 경우 각 기능의 상태 코드만 확인한다. 자격이나 본문은 출력하지
   않는다.

공개 베타 주소가 `https://relayer.kr/test`로 제공되는 경우에도 기관 운영자는 실제
배포 주소와 접근 정책을 별도로 관리한다.

## 관리형 주소와 기관별 배포

앱 하나가 하나의 기관을 담당하도록 배포하면 데이터 경계와 백업이 단순해진다. 주소는
배포 설정의 `RELAYER_SLUG` 또는 `RELAYER_PUBLIC_URL`로 정하고, 앱 화면에서는 읽기
전용으로 보여 준다. DNS와 HTTPS는 조직이 승인한 관리형 DNS·터널·리버스 프록시를
사용한다. 내부 서비스 주소나 프록시 설정값을 저장소에 적지 않는다.

## 백업과 복구

- 데이터베이스 백업의 보존 기간·암호화·접근 권한을 정한다.
- 음성·문서 파일은 데이터베이스와 별도의 보존·삭제 정책을 정한다.
- 백업에서 격리된 환경으로 정기 복구 리허설을 하고, 테스트 데이터는 끝난 뒤 삭제한다.
- 복구 시 `PII_ENC_KEY`를 먼저 확보한다. 키 없이 암호화된 개인정보를 복구할 수 없다.

## 비밀값 회전

1. 제공자에서 새 자격을 발급하고 비밀 관리 시스템의 값을 갱신한다.
2. 새 값으로 애플리케이션을 재시작하고 `/health`, 로그인, 암호화 기록 조회를 확인한다.
3. AI·음성 등 사용하는 기능의 상태 코드만 확인한다.
4. 새 배포가 정상인 뒤 이전 자격을 폐기한다.

비밀값이 노출되었다면 정상 회전 순서를 기다리지 말고 제공자에서 즉시 폐기한다. 모든
진단·감사 기록에는 commit, 경로, 오류 범주만 남기고 비밀값이나 전체 요청을 남기지
않는다.
