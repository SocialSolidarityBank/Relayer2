# 운영자 절차 (값 없는 참고)

이 문서는 릴레이어를 운영하는 담당자가 배포·점검·회전 순서를 정할 때 참고하는
일반 절차다. 호스트 이름, 사용자 경로, 프로젝트 식별자, 비밀 저장소 경로, 자격 식별자,
민감한 식별자와 비밀값은 기록하지 않는다. 각 환경의 실제 값은 조직의 접근 통제된 운영
문서와 비밀 관리 시스템에서 관리한다.

## 신규 환경 준비

1. 애플리케이션을 실행할 기관 전용 호스트나 관리형 실행 환경을 준비한다.
2. PostgreSQL 데이터베이스와 백업 정책을 준비하고, 애플리케이션 전용 계정에 최소
   권한을 부여한다.
3. `docs/secrets.md`의 필수 환경 변수를 생성한다. 개인정보 암호화 키는 별도의
   안전한 보관 위치에도 백업하되, 데이터베이스 백업과 같은 위치에는 두지 않는다.
4. 사용하려는 AI·음성 제공자의 선택 변수를 추가한다. 사용하지 않는 기능은 비워 두고
   기능이 비활성화되었는지 확인한다.
5. 비밀 관리 시스템에서 배포 대상의 프로젝트·환경·경로를 만들고, 배포 자동화에는
   해당 범위만 읽고 쓸 수 있는 회전 가능한 자격을 부여한다.

## 배포

1. 승인된 릴리스 아티팩트를 배포한다. 소스 저장소의 작업 트리나 개인 홈 디렉터리를
   운영 기준으로 문서화하지 않는다.
2. 비밀값을 명령행 인자나 `docker run -e NAME=value`로 넘기지 않는다. 권한이
   제한된 환경 파일 또는 런타임 비밀 주입 기능을 사용한다.
3. 시작 전에 필수 변수의 **이름과 존재 여부만** 확인한다. 값, 토큰, 연결 문자열은
   출력하지 않는다.
4. 데이터베이스 마이그레이션을 승인된 순서로 적용한 뒤 애플리케이션을 시작한다.
5. HTTPS 역방향 프록시나 관리형 도메인을 사용할 경우 외부에는 필요한 공개 제품
   엔드포인트만 노출하고, 데이터베이스·관리 포트는 공개하지 않는다.
6. `/health`의 성공 응답과 로그인, 암호화된 기록의 조회를 확인한다. AI·음성을
   사용하는 환경에서는 각 기능의 상태도 값 없이 확인한다.

## 백업과 복구

- 데이터베이스 백업은 보존 기간·암호화·접근 권한을 정하고 정기적으로 복구 리허설을
  한다.
- 음성·문서 저장소를 사용할 경우 데이터베이스와 별도로 보존 기간과 삭제 스윕을
  관리한다. 공개 URL로 파일을 제공하지 않는다.
- 백업 로그에는 파일 내용, 개인정보, 연결 문자열, 키가 포함되지 않도록 한다.
- 복구 리허설은 격리된 환경에서 실행하고, 확인 뒤 테스트 데이터를 삭제한다.
- 암호화 키 복구가 가능한지 먼저 확인한 뒤 데이터 복구를 진행한다.

## 회전과 장애 대응

1. 제공자 키·데이터베이스 자격·자동화 자격 중 하나가 노출되었거나 만료되면 즉시
   제공자에서 폐기·회전한다. 기존 값을 로그나 문서에서 찾으려 하지 않는다.
2. 비밀 관리 시스템의 새 값을 배포 대상에 주입하고 애플리케이션을 재시작한다.
3. 상태 코드, 연결 성공 여부, 최근 오류의 범주만 기록한다. 원문 비밀값이나 전체
   요청 헤더는 기록하지 않는다.
4. 새 배포가 정상임을 확인한 뒤 이전 자격을 폐기하고, 접근 권한과 감사 로그를
   검토한다.
5. `PII_ENC_KEY`를 회전할 때는 기존 암호문을 계속 읽을 수 있는 키 관리·마이그레이션
   계획 없이는 회전하지 않는다.

## 공개 운영 점검표

- [ ] 필수 환경 변수 세 개가 모두 주입됨
- [ ] 환경 파일과 비밀 저장소의 접근 권한이 최소화됨
- [ ] `/health`가 성공하고 로그인과 암호화된 기록 조회가 됨
- [ ] 공개 엔드포인트 외의 관리·데이터베이스 포트가 차단됨
- [ ] 백업 생성과 복구 리허설 일정이 있음
- [ ] 로그·모니터링에 비밀값과 개인정보가 없음
- [ ] 자격 회전·폐기 절차와 담당자가 정해짐
