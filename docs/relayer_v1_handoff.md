# Relayer2 상담기록 v6 개발자 핸드오프 프롬프트

> 아래 문서 전체를 레포 접근 권한이 있는 개발자 또는 코딩 에이전트에게 전달한다. 이 문서는 소스 정적 분석과 구현 지시서이며, 코드 수정·마이그레이션·테스트 실행·배포 결과가 아니다.

## 1. 역할과 목표

당신은 `SocialSolidarityBank/Relayer2`의 상담기록 기능을 수정하는 개발자다. 첨부 v6 규칙에 따라 **수기 원문 보존 → 회차 내부 구조화·상태 판정 → 전사 전문 연결·불일치 대조 → 회차별 요약**을 구현하라. 기존 React 앱과 API에 통합하고, 별도 목업만 만든 뒤 완료로 처리하지 마라.

이번 요청의 산출물은 구현 계획과 검수 기준이다. **사용자가 구현을 지시하기 전에는 코딩하지 않는다.** 구현 지시를 받은 경우 아래 요구사항과 완료 기준을 따른다. Git push·병합·배포는 별도 요청 범위다.

### 현재 데이터 흐름

1. 수기 기록은 `sessions.memo` 및 수기 카드 등에 저장된다. `cards.source_type`은 `manual`과 `ai_approved`를 구분한다.
2. `POST /sessions/:id/draft` → `draftSession()` → 현재 회차 memo·카드 + **이전 완료 회차들의 자료** → 마스킹 → LLM → `ai_drafts` 초안.
3. 현재 AI 계약은 `summary / changes / tasks / questions / fact_changes`이다. `changes`와 `fact_changes`가 회차 간 비교를 지시한다. 프롬프트에는 서로 다른 말 중 나중 말을 사용하라는 규칙도 있다.
4. 사람 승인 → `approveDraft()`가 승인 행을 추가하고, 과제·질문은 같은 트랜잭션에서 `ai_approved` 카드로 반영한다. 승인 전 요약은 정식 회차 요약에 노출되지 않는다.
5. 회차별 요약 UI는 승인 요약과 `GET /cases/:id/briefing`의 현재 과제 상태를 조합한다. 과제의 출처 회차만으로 분류하므로 **후속 회차에서 완료된 결과가 과거 회차의 완료 영역에 들어갈 수 있는 구조**다.
6. 녹음 업로드 → STT → 마스킹한 전사 본문·segments를 암호화하여 `transcripts`에 추가한다. 본문 수정 승인 시 기존 segments는 버린다. 최신 전사는 회차 전체에서 `order by id desc limit 1`로 조회한다.
7. 원본 드로어는 segments가 있으면 segments를, 없으면 본문 전체를 표시한다. 구간 재생은 있으나 문장별 수기 연결·상태 CSS 하이라이트·클릭 대조 패널은 없다.
8. `getMismatches()`는 현재 memo, 최신 전사, 직전 수기 기록을 읽는다. `voiceVsWritten()`은 일부 숫자 패턴의 값 차이만 비교하고 같은 속성의 마지막 값을 사용한다. `acrossSessions()`도 함께 반환한다.

### 현재 구현과 v6의 차이

| 현재 구현 | v6 요구와 구현 방향 |
|---|---|
| AI에 이전 회차 전달, 회차 간 changes 생성 | 새 분석은 현재 회차만 전달. 회차 간 비교를 새 요약·상태·불일치에서 분리 |
| 단일 summary와 문자열 배열 | 원문 참조를 가진 구조화 기록·상태·3개 요약 하위 영역 계약 필요 |
| 현재 브리핑 상태로 과거 회차의 확인/완료 표시 | 현재 회차 증거로 고정된 요약 필요. 다음 회차 결과로 과거 요약 보강 금지 |
| memo·카드 단순 나열 | 큰 주제 → 세부 단락 → 수기 원문 3단계 구조 필요 |
| 숫자 라벨이 같고 값이 다르면 불일치 | 대상·속성/사건·시기·양립 불가 4조건을 모두 확인해야 함 |
| 회차 최신 전사 1건 | 녹음 파일이 여럿이면 파일별 최신 버전을 포함해야 함. 버전 중복과 파일 누락 구분 |
| segment에 text/offset/duration만 있음 | 원문 범위 ID, 회차·파일·버전 식별, 실제 제공된 화자 정보 필요 |
| 일부 segments만 존재해도 본문 대신 표시 | segments가 본문 전부를 덮는지 검증. 누락 시 부분 전사 완료 금지 |
| `자동 전사라 틀린 곳 있음` | 정본의 `자동 전사본이라 틀린 부분이 있을 수 있습니다.`로 통일 |
| 빈 분류에 `없음` 문구를 항상 표시 | 내용 없는 요약 분류 숨김, 남은 하위 항목 번호 재부여 |
| 인테이크 표현 잔존 | 사용자 노출 이름은 `첫상담 기록`으로 통일. DB enum/라우트의 intake는 유지 가능 |

## 3. 적용 우선순위와 해석 결정

### 확정 규칙

- 사실 확정의 기준은 해당 회차 수기다. 전사는 보조 자료다.
- 수기·전사 원문은 별도로 보존한다. AI가 원문을 다시 작성하게 하지 않는다.
- 회차별 요약은 구조화된 상담 기록에서 추출한다.
- 🔵 실제 변화는 해당 회차의 수기 안에 변화 전후·실제 변화·상담상 의미가 모두 있어야 한다.
- **예외는 02의 `상담 중 새로 드러난 것`에만 적용**한다. 전후가 없어도 해당 회차 수기에 근거한 의미 있는 내용은 요약에 포함 가능하다. 이를 01 또는 04의 파란색 상태로 전파하지 않는다.
- 🟠는 후속 확인이지 미이행·미완료 판정이 아니다. 🟢는 실제 완료·해결 증거가 있어야 한다.
- 불일치는 같은 회차의 수기와 전사 사이에서만 판정한다. 어느 쪽도 자동 정답으로 확정하지 않는다.
- 전사 전문 보존·문장 연결·실제 하이라이트 검증이 실패하면 완료로 처리하지 않는다.

### 정본 내 표현 차이를 구현할 때 적용할 해석

| 쟁점 | 적용할 해석과 근거 |
|---|---|
| 공통 문서의 ‘모든 변화는 전후 필요’ | 실제 변화 판정에 적용. 같은 문서 및 01·02·04의 명시적 요약 전용 예외는 유지 |
| 04 말미는 ‘네 항목’이라고 쓰고 3개만 열거 | 04 본문·공통 HTML에 일치하는 4개: 차이점 / 녹음 내용 / 수기 내용 / 연결된 수기 단락 |
| 번호 예시 일부에서 ① 누락 | 반복 명시된 연속 번호 규칙을 적용. 빈 항목 제거 후 ①부터 부여 |
| 전사 전문에는 요약 금지, 요약 화면에는 요약 필요 | 전문 보존 규칙을 전사 원문 영역에 적용. 02 영역의 근거 있는 요약까지 금지하지 않음 |
| 시간·화자 검수 vs 없는 정보 생성 금지 | 값이 있으면 그대로 보존. 없으면 null 및 구간 번호·미확인 표시, 가짜 시간·화자 생성 금지 |
| 줄임표 금지 vs 원문 보존 | 원문에 있던 `…`는 보존. 생성기가 생략 표시로 새로 넣는 줄임표·중략은 금지 |
| 미확인 불일치와 수기 원문 보존 | 원문은 삭제하지 않고 그대로 보여 주되 불일치 연결을 표시. 쟁점 내용을 새 요약의 확정 사실로 재진술하지 않음 |

### 기존 레포 설계와 충돌하는 부분

`DESIGN.md`에는 원본 버튼을 요약에서 제거, 드로어 사용, 3단 아코디언 미채택, 이모지 제목 미사용이 명시되어 있다. `GLOSSARY.md`에는 회차 간 불일치와 인테이크 명칭이 남아 있다. 이는 이번 첨부 규칙과 실제 충돌한다.

이 핸드오프의 적용안은 **이번 첨부 규칙을 기능·화면 명세로 우선**하는 것이다. 회차 헤더의 `상담 기록 보기`·`녹음 전사 보기`, 3단 수기 계층, 2단 전사 대조와 고정 분류를 구현하고 관련 문서를 함께 갱신한다. 기존 `SessionOriginalDrawer`의 dialog·포커스·닫기 동작은 재사용 가능하지만 기존 폭·단일 컬럼 때문에 요구 기능을 생략해서는 안 된다. 모바일에서는 대조 패널을 아래에 배치한다.

단일 HTML·Tailwind CDN 지시는 독립 결과물 생성용 형식이다. 이번 **레포 통합의 제안**은 React 컴포넌트와 기존 CSS에 동일한 동작을 구현하는 것이며 앱을 단일 HTML로 교체하지 않는 것이다. 독립 HTML 내보내기까지 요구받으면 별도 산출물로 같은 검수 기준을 적용한다. 이를 이미 제공하는 기능이라고 주장하지 않는다.

기존 수기 위험 기록·권한·동의·감사·사람 승인·15초 다시보기의 업무 이력은 유지한다. 다만 AI 회차별 요약 안에 위험 신호·기록 상태를 추가 최상위 분석 분류로 섞지 말고 기존 운영 정보와 분리한다. 과거 회차 비교 기록은 삭제하지 않으며 새 v6 결과의 근거로 사용하지 않는다.

## 4. 목표 데이터 흐름

1. 회차와 원본 버전을 식별한다. 수기/전사 자료의 원문·줄·문자 범위·실제 시각·실제 화자를 등록한다.
2. 해당 회차의 **수기 원본**으로 계층 구조와 상태 후보를 만든다. 원문 텍스트는 저장된 범위를 참조한다.
3. 같은 회차의 전사 전문을 읽고 문장 단위 수기 연결 후보를 만든다. 연결할 수 없는 문장은 연결 없음으로 남긴다.
4. 연결된 원문 쌍에 대해 불일치 4조건을 검증한다. 불일치 원문은 유지하되 쟁점 후보가 사실로 확정되지 않도록 한다.
5. 01의 엄격한 상태를 검증하고, 04는 이 상태만 수기 연결을 통해 표시한다.
6. 구조화 기록 + 상태 + 불일치 상태에서 02 요약을 만든다. 요약 전용 예외는 별도 플래그로 저장한다.
7. 스키마·참조 범위·원문 무손실·회차 격리 검증 후 초안으로 저장한다. 사람 검토·승인을 거쳐 정식 표시한다.
8. React UI는 원문과 분석 데이터를 결합해 렌더링한다. 원문을 LLM 출력으로 대체하지 않는다.
9. 수기 수정·전사 재생성·사람 수정 시 기존 분석을 오래된 결과로 표시하고 재분석·재검토한다. 승인 이력과 원본은 덮어쓰지 않는다.

원본 표시 경로는 LLM 성공 여부와 독립적이어야 한다. 분석 실패가 원문 누락·빈 화면으로 이어지면 안 된다. 긴 자료는 분석만 분할 처리하며 전문 렌더링은 항상 전체 원본 저장소에서 읽는다.

## 5. 데이터 계약 제안

아래 이름은 **신규 설계 제안**이다. 현재 DB에 존재하는 것으로 오해하지 마라. 실제 필드 이름은 기존 스타일에 맞추되 다음 관계·검증 조건을 충족하라.

| 엔티티 | 필수 정보와 검증 |
|---|---|
| SourceDocument | case_id, session_id, source_type, source_id, revision/hash, 원문, 인코딩·줄바꿈 기준. 원문은 암호화 정책 적용 |
| SourceSpan | document_id, revision, start/end 범위, 순서. 범위 밖·다른 회차 참조 거절 |
| StructuredParagraph | 안정 ID, 큰 주제/단락 제목, 원문 참조 목록, 원문 순서. 같은 원문 중복 배치 금지 |
| MeaningAnnotation | paragraph/span 참조, change/follow_up/completed, 근거 참조. 실제 변화는 before/after 증거 필수 |
| TranscriptUnit | session_id, recording/source ID, transcript version, stable unit ID, 원문 범위, 원래 순서, time/speaker nullable |
| EvidenceLink | transcript span ↔ written span/paragraph, same-session 보장, match/unmatched/uncertain 구분 |
| Discrepancy | 연결 ID, 4조건별 확인 결과와 근거 참조, 미확인/해결 상태, 원문 인용. 내부 점수·추론 전문 저장/노출 불필요 |
| SessionSummaryV6 | core, change 하위 3종, follow_up, completed. 각 항목은 수기 참조와 근거 보유 |
| Summary change item | subtype: promise_result/newly_revealed/new_possibility; actual_change 여부; summary_only_exception 여부 |
| AnalysisRevision | schema_version, rule_version, source revision/hash 묶음, draft/approved 상태, 검증 결과, 생성·승인자/시각 |

구현 조건:

- 화면 번호는 데이터 ID로 쓰지 않는다. 문장 위치와 버전 식별을 결합해 중복 발화도 각각 참조 가능하게 한다.
- offset 기준을 명시한다. 예: JS UTF-16 인덱스. 한글·이모지·줄바꿈에서 범위와 인용문이 일치하는지 시험한다.
- `source_type=ai_approved` 카드를 수기 원본인 것처럼 재투입하지 않는다. `sessionParts()`는 현재 모든 카드를 읽으므로 출처 필터가 필요하다.
- `getSessionRecord()`의 cards 응답에는 현재 카드 ID·source_type이 없다. 분석용 조회에 이를 제공하거나 별도 내부 DTO를 만든다.
- 목표가 이전 회차에서 이어받은 값이면 현 회차 변화 판정의 이전 상태로 쓰지 않는다. 출처 정보를 유지한다.
- 단일 status 문자열에 불일치와 중요 의미를 합치지 않는다. 한 문장에 상태 띠와 불일치 배경이 함께 표시될 수 있어야 한다.
- 기존 AI 문자열을 근거 없이 v6 유형으로 자동 변환하지 않는다. 구버전으로 구분하고 새 분석은 원본에서 생성한다.
- 현재 AI JSON은 `JSON.parse(...) as Shape` 중심이다. 새 계약은 런타임 스키마 검증과 의미/참조 검증까지 추가한다.

## 7. 모듈별 구현 요구사항

### A. 원본 수집·보존

- 메모와 전사 원문은 문자·어휘·오탈자·반복·줄바꿈을 유지한다. 화면 제목과 원문 저장 영역을 분리한다.
- 자료가 실제 있는 모든 회차를 표시하고 회차 목록은 최신순, 회차 안 전사는 원래 시간/순서대로 표시한다. 존재하지 않는 회차·날짜·상담 목표를 생성하지 않는다.
- 한 회차에 녹음 파일이 여럿이면 파일별 최신 대상 버전을 읽는다. 별도 파일의 00:00들을 하나의 공통 00:00으로 섞지 않는다. 파일 순서가 확인되지 않으면 추정 순서를 만들지 않는다.
- 전사 본문 전체와 segment coverage를 대조한다. 일부 segment만 있다고 나머지 본문을 버리지 않는다. 구간 정보가 부족하면 본문 전체를 보존하고 결손을 표시한다.
- 현재 STT는 본문을 trim/join하고 일부 시각 없는 phrase를 segments에서 제외한다. 공급자 출력→저장 단계부터 보존 경계를 정의해야 한다.
- 현재 저장된 전사는 마스킹 후 본문이다. 마스킹 전 원문·없던 화자·없던 시각을 역추정해서 복원하지 않는다. 이미 저장된 자료의 검증 기준은 실제 확보된 버전이라고 명시한다.
- 새 원본 보존 설계는 기존 동의·마스킹·암호화·보유기간 계약 안에서 구현한다. 마스킹 전 원본을 새로 저장해야 하는 경우 저장 범위/보유기간을 별도 설계 결정으로 제시한다. 원문 보존 요구만으로 기존 외부 전송 보호를 해제하지 않는다.
- 외부 AI에 마스킹된 내용을 보낼 때 원문 offset과 마스킹 후 offset이 달라지는 문제를 처리한다. 서버가 관리하는 span ID로 원문을 다시 참조하고 모델이 개인 정보를 복원하지 않게 한다.

### B. 01 구조화 기록

- 큰 주제 `01, 02…` → 세부 단락 `1-1, 1-2…` → 원문 계층. 제목도 원문 핵심 어휘로 만든다.
- 수기 시간 순서를 유지한다. 주제 묶음을 위해 뒤의 문장을 앞으로 옮기지 않는다. 같은 주제가 다시 나오면 연속된 원문 구간 단위로 배치하거나 참조한다.
- 본문은 원본 참조로 렌더링한다. LLM이 반환한 원문 복제 문자열은 진실의 원천으로 사용하지 않는다.
- 변화 6유형은 내부 기준으로만 사용한다. 사용자 제목·뱃지·괄호 라벨로 노출하지 않는다.
- 중요 문장만 상태 표시한다. 원문 전체에 색을 칠하지 않는다.
- 동일 사건 중복 분류는 가장 구체적인 결과를 중심으로 정리한다. 실제 별개 결과는 별도로 남길 수 있다.

### C. 02 회차별 요약

- 최상위 4개 영역만, 정본 순서대로. 핵심은 1~2개 짧은 문장.
- 파랑 하위 의미 순서: 약속 이행 여부 → 상담 중 새로 드러난 것 → 이번 상담 후 새로운 가능성.
- 내용 없는 항목을 제거한 뒤 ①부터 번호를 계산한다. 번호를 subtype에 저장하지 않는다.
- 약속과 실제 결과는 같은 회차 수기에 모두 있어야 한다. 결과가 없으면 이 하위 영역을 숨긴다. 필요하면 별도로 후속 확인에 담는다.
- 새로 드러난 것의 예외에는 `확인된 내용:`을 사용한다. 실제 전후가 있을 때만 `변화점:`·화살표를 사용한다.
- 새로운 가능성은 같은 회차의 변화와 후반부 합의/계획의 실제 연결이다. AI 전망이 아니다.
- 직접 인용은 실제 수기 기록에 존재할 때만 허용한다. 수기 메모를 실무자/당사자 대사로 재구성하지 않는다.
- ‘노력’을 ‘시도’로, ‘상담’을 ‘멘토링’으로 바꾸지 않는다. 요약은 선택적 축약이지 동의어 재작성 작업이 아니다.
- `하기로 함`은 해당 과제 완료가 아니다. 상담 안에서 ‘결정/정리가 완료됨’과 그 결정에 따른 미래 과제 완료를 구분한다.
- 현재 브리핑의 open/closed 상태를 직접 요약 자료로 쓰지 않는다. 회차 당시 수기의 증거와 동일 회차 내 결과만 사용한다.

### D. 04 전사·하이라이트·불일치

- 전사 존재 시 전문과 정확한 안내문을 표시한다. 없음은 `첨부된 녹음 전사본이 없습니다`. 로딩·접근 거절·전사 실패를 자료 없음과 혼동하지 않는다.
- 모든 문장의 원문 위치를 확보하되 모든 문장을 수기에 억지 연결하지 않는다. 매칭 없음/불확실도 명시적으로 관리한다.
- 상태 하이라이트는 01에서 확정된 상태만 상속한다. 전사만으로 새로운 변화·완료를 생성하지 않는다.
- 일반 연결과 상태 띠, 불일치 배경을 구분한다. 상태 없는 일반 연결은 중립적으로 표시한다.
- 불일치는 동일 대상·속성/사건·시간 범위·양립 불가가 모두 확인된 경우만. 하나라도 불명확하면 확정 불일치로 표시하지 않는다.
- 숫자 차이는 후보일 뿐이다. ‘본인 월세 40만 원’과 ‘어머니 월세 50만 원’을 같은 라벨이라는 이유로 비교하지 않는다.
- 수기 누락·어휘 차이·더 구체적인 설명은 불일치가 아니다. 실제 정정이나 다른 시간 범위도 문맥을 보고 구분한다.
- 불일치 문장 클릭 시 `차이점 / 녹음 내용 / 수기 내용 / 연결된 수기 단락`만 있는 패널을 갱신한다. 다른 문장 클릭 시 실제 데이터가 바뀌어야 한다.
- 일반 연결 문장 클릭도 연결 원문으로 이동한다. 불일치가 아닌 문장에 차이를 만들어 넣지 않는다.
- `기록 불일치 모아보기`는 판정된 문장만 필터링한다. 필터 해제 시 전문을 복원한다. 필터 표시를 ‘원문 누락’과 혼동하지 않도록 상태를 드러낸다.
- 클릭한 연결 단락은 펼치고 이동·초점을 제공한다. 모바일에서는 하단 패널, 키보드 선택·Escape·초점 복귀도 지원한다.
- 원문을 HTML 문자열로 실행하지 않는다. 텍스트 노드와 안전한 범위별 span을 사용한다. 겹치는 강조도 원문 문자를 중복 삽입하지 않는다.

### E. 저장·승인·호환성

- 기존 `draft → 사람 승인 → approved` 흐름을 유지한다. 원문 보기 자체는 요약 생성/승인에 종속시키지 않는다.
- 새 AI 승인에는 보고 있던 draft ID와 원본 버전 확인을 추가한다. 다른 초안이나 수정된 수기를 오래된 분석으로 승인하지 않는다.
- 현재 전사 불일치 비교는 승인된 전사에만 실행된다. 기본 통합안도 이 검토 게이트를 유지한다. 확인 전 전사는 전문 열람 가능하되 대조 미실행 상태를 정확히 표시한다. 자동 전사 초안 단계 대조까지 확대하는 경우 별도 계약으로 구분하고 사실 승인과 혼동하지 않는다.
- 원본·불일치 출처는 잠금, 사람의 요약 수정은 새 초안/승인 이력으로 기록한다. 수정으로 근거가 사라지면 유효한 연결인 것처럼 유지하지 않는다.
- 분석 생성 실패·시간 초과·응답 잘림은 초안 실패 상태로 남긴다. 일부 분석으로 전체 완료를 표시하지 않는다.
- 기존 원문과 승인 데이터를 파괴적 변환하지 않는다. additive migration으로 새 계약을 추가하고 구버전 조회·새 버전 재생성을 구분한다.

## 8. 이전 테스트에서 가져올 회귀 기준

아래는 이전 대화에서 보고된 결과다. **이번 작업에서 원본 테스트 HTML과 상담 원문 파일을 다시 실행·검증한 결과는 아니다.** 현재 첨부에는 규칙 5개만 있으므로 실제 상담 데이터 기반 골든 테스트는 원본 확보 후 고정해야 한다.

| 이전 보고 | 이번 구현의 회귀 기준 |
|---|---|
| 전사 전문 대신 일부만 요약 타임라인으로 넣고 `…`로 생략 | 원문 무손실 재구성 + 줄/문자/구간 coverage 검증 |

이전에 불일치로 보고된 ‘AI 프로젝트 우선순위’와 ‘회사에 남아 공부’ 사례도 정답 레이블로 그대로 쓰지 않는다. 같은 회차·대상·시간·최종 합의 문맥을 원본으로 다시 확인해야 한다. ‘프로젝트 1차 완료’ 역시 전사에만 있는지, 수기에 있는지, 불일치인지에 따라 달라진다. **완료라는 단어만으로 🟢를 붙이지 않는다.**

실제 상담 텍스트는 공개 레포에 테스트 fixture로 커밋하지 말고, 회귀 테스트에는 같은 논리 구조의 합성 데이터를 우선 사용한다.

### 테스트 방법과 통과 증거

- 원문 보존은 줄 수만으로 통과시키지 않는다. 원본 revision/hash, raw line count, 문자 수, span coverage, 중복/누락 범위, DOM에서 원문만 재구성한 비교 결과를 함께 남긴다. 화면 줄바꿈에 따른 시각적 줄 수와 원본 줄 수를 혼동하지 않는다.
- 원문 UTF-8 파일 bytes hash와 파싱 후 문자열 비교를 분리한다. CRLF/LF 변환을 허용한다면 정책·비교 방식과 원본 bytes 보존 위치를 명시한다.
- HTML의 전체 innerText가 아니라 원문 컨테이너의 source span만 수집한다. 제목·시간 라벨·대조 인용이 원문 건수에 중복 계산되지 않게 한다.
- 색 클래스 존재만 보지 말고 계산된 스타일, 클릭 가능성, 다른 항목 선택 시 패널 갱신, 링크 대상 단락 펼침까지 확인한다.
- 의미 판정은 사람이 검토한 합성 골든 케이스와 모델 반환값 검증으로 시험한다. 프롬프트 문구가 있다는 이유로 정확성을 보장하지 않는다.
- 실제 상담 원문 테스트는 확보 후 별도 실행한다. 자료 미확보를 합성 테스트 통과로 대체하지 않는다.

### 실행 명령

기존 코드에 있는 실행 체계를 우선 사용한다. 아래는 **구현 이후 실행할 명령**이며 이번 문서 작성 중 실행한 결과가 아니다.

```bash
pnpm install --frozen-lockfile
pnpm --dir api exec vitest run
pnpm --dir web exec tsc --noEmit
pnpm --dir web build
node scripts/check-case-access.mjs
pnpm --dir web exec playwright test e2e/record-analysis-v6.spec.ts --reporter=line
pnpm --dir web exec playwright test e2e/beta-flow.spec.ts e2e/voice-start.spec.ts e2e/user-feedback.spec.ts --reporter=line
```

`check-case-access.mjs`는 localhost PostgreSQL에 임시 DB를 만들고 모든 API 테스트를 실행하는 기존 스크립트다. 일반 `vitest run`만으로는 `RELAYER_INTEGRATION=1` 조건의 통합 테스트가 skip될 수 있으므로 통합 통과로 보고하지 마라. Playwright는 API 8787·web 5173·로컬 DB가 미리 실행되어 있어야 한다. 테스트는 합성 자료와 격리 DB, 외부 AI/STT stub으로 실행한다.

## 10. 구현 순서

1. 현재 HEAD·작업 트리·관련 지침을 확인하고 위 분석 커밋 이후 변경을 대조한다. 분석 대상 파일·현재 계약을 짧게 재확인한다.
2. 원문/근거/버전 계약과 legacy 호환 계획을 정한다. 특히 다중 녹음, 마스킹과 원문 범위, 사람 수정 전사 버전을 먼저 해결한다.
3. 합성 fixture와 원문 무손실·회차 격리·파랑 예외 테스트를 만든다.
4. 원본 보존·연결/판정 validator·저장/승인 경로를 구현한다. 기존 동의/접근검사와 카드 승인 트랜잭션을 연결한다.
5. 01 구조화, 02 요약, 04 전체 전사·하이라이트·대조 UI를 공용 데이터 계약으로 구현한다.
6. 구버전 호환·stale 결과·실패/빈 상태·모바일·인쇄를 확인한다.
7. 실제 실행 로그와 원문 coverage, 브라우저 클릭 증거로 검수한다. 정본 문서와 레포 문서의 충돌 구절을 갱신한다.

## 11. 완료 기준

다음 조건이 모두 충족되어야 ‘v6 적용 완료’라고 보고할 수 있다.

- [ ] 지정한 커밋/브랜치 기준과 실제 수정 파일 목록이 남아 있다.
- [ ] 제공된 모든 회차·수기·전사 원문이 버전별로 보존되고, 표시 대상 전문에 누락·원치 않는 중복이 없다.
- [ ] 원본 보존을 LLM 재출력에 의존하지 않는다.
- [ ] 수기 3단 구조와 정확한 요약 4영역·파랑 3하위항목·연속 번호가 구현되었다.

- [ ] 후속 회차 완료가 과거 회차 요약을 바꾸지 않는다.
- [ ] 요약 전용 예외가 상세·전사의 파란색 상태로 전파되지 않는다.
- [ ] 전사 전문, 실제 CSS 강조, 문장 클릭, 4항목 대조, 연결 단락 이동, 필터 복원이 브라우저에서 작동한다.
- [ ] 불일치 4조건, 어휘 보존, 전사 단독 사실 확정 금지 테스트가 통과했다.
- [ ] 사람 승인·버전 충돌·권한·동의·마스킹·감사·기존 카드 흐름의 회귀가 통과했다.

- [ ] 구버전 자료를 훼손하지 않고 migration·조회 호환이 확인되었다.
- [ ] 합성 테스트와 실제 자료 검수를 구분하고, 실제 자료 검수가 필요하지만 미실행이면 그 제한을 명시했다.
- [ ] 테스트 명령·통과/실패/skip·미해결 사항·화면 증거·원문 coverage 보고서를 제출했다.

원문 누락, 클릭 미동작, 잘못된 파랑 전파, 회차 범위 위반, 불일치 과잉 판정, 빈 화면 중 하나라도 남아 있으면 전체 완료로 보고하지 마라. 원본 자료가 없어 검수할 수 없는 항목은 ‘검증 대기’로 남긴다.

## 1\. 기존 수기 구조 및 원형 보존

실무자가 작성한 수기 기록의 문장, 어휘, 오탈자, 줄바꿈 구조를 최우선으로 유지한다.

### 금지 사항

* 원문 재작성 또는 정제라는 명목의 단어 변형
* 상담에 등장하지 않은 배경 정보 추가
* 감정·의도·진단·관계를 자의적으로 추정
* 녹음 전사만을 근거로 새로운 사실을 확정

### 원문 어휘 고정 규칙

이 규칙은 수기 원문 본문뿐 아니라 **큰 주제 제목, 세부 단락 제목, 중요 의미와 연결되는 설명 등 상담 사실을 다시 표현하는 모든 생성 문구**에 적용한다.

* 상담 사실을 표현할 때 사용하는 핵심 명사·동사·형용사는 **수기 기록에 실제로 등장한 어휘를 우선 그대로 사용**한다.
* 원문에 있는 단어를 AI가 더 자연스럽거나 전문적으로 보이게 하려고 **동의어·유사어·상위 개념·전문 용어로 바꾸지 않는다.**
* 원문이 `노력했다`라고 쓰면 `시도했다`로 바꾸지 않는다.
* 원문이 `상담했다`라고 쓰면 원문에 없는 `멘토링했다`로 바꾸지 않는다.
* 원문이 `이야기함`, `말함`, `약속함`, `참여함`, `신청함`, `등록함` 등으로 기록되어 있으면 가능한 한 그 동사를 그대로 유지한다.
* 문장을 짧게 만들 필요가 있을 때는 **원문의 일부를 덜어내는 방식으로 축약**하고, 남은 의미를 다른 단어로 치환하여 다시 쓰지 않는다.
* 문장 연결을 위해 필요한 조사·어미·접속 표현은 최소한으로 조정할 수 있으나, 사건·행동·상태를 나타내는 핵심 어휘는 바꾸지 않는다.
* 큰 주제와 세부 단락 제목도 가능한 한 원문에 등장한 핵심 단어를 조합해 작성한다. 제목을 만들기 위해 원문에 없는 해석어를 새로 붙이지 않는다.
* 녹음 전사는 보조 자료이므로, 사실로 확정해 표시하는 구조화 기록의 용어는 수기 기록에 사용된 표현을 우선한다.

## 3-1. 🔵 이번 회차에서 확인된 변화 판정

`이번 회차에서 확인된 변화`는 **이전 회차와 비교하여 판정하지 않는다.**

판정 범위는 **오직 현재 회차 내부**로 한정한다.

* 이전 회차의 상담 내용, 과제, 약속, 계획, 상태를 가져와 비교하지 않는다.
* 현재 회차 안에서 나온 약속·과제·실행 계획과, 같은 회차 안에서 실제로 확인된 수행 결과만 연결할 수 있다.
* 현재 회차 안에서 확인되는 `초기/기존 상태 → 달라진 상태` 또는 `계획·의향 → 결정·실행`의 흐름을 기준으로 판정한다.

단순히 이번 회차에서 처음 알게 된 사실은 변화로 보지 않는다.

### 변화 유형 6가지

1. **행동 변화**

   * 하지 않던 행동을 시작함
   * 거부하던 행동에 응함
   * 실제 행동 방식이 달라짐
2. **태도 변화**

   * 거부·경계·소극적 태도가 수용·협조·참여 등으로 달라짐
   * 또는 그 반대 방향의 유의미한 변화가 확인됨
3. **상태 변화**

   * 신체·정서·생활·기능 등의 상태가 해당 회차 안에서 개선·악화 또는 변화함
4. **결정 변화**

   * 망설이거나 거부하던 사안에 대해 구체적인 선택·동의·거부·계획을 결정함
5. **실행 진전**

   * 논의·계획·의향 수준에서 신청·접수·진료·참여·연계·계약 등 실제 실행 단계로 넘어감
6. **관계 변화**

   * 가족·기관·실무자·지원자 사이의 협조, 역할 분담, 갈등, 신뢰 등 관계 구조가 실제로 달라짐

### 표시 조건

다음 3가지 조건을 모두 만족할 때만 🔵로 표시한다.

1. **실제 변화가 확인됨**

   * 가능성이나 예상이 아니라 기록에서 실제 변화가 확인되어야 한다.
2. **변화 전후가 확인됨**

   * 같은 회차 안에서 변화 전 상태와 변화 후 상태를 연결할 수 있어야 한다.
3. **상담상 의미가 있음**

   * 상담 목표, 후속 조치, 서비스 이용, 가족 기능, 생활 상태 등 상담 진행에 의미 있는 영향을 주어야 한다.

### 변화로 보지 않는 경우

다음은 🔵로 표시하지 않는다.

* 이번 회차에서 처음 알게 된 사실일 뿐 변화 전후가 확인되지 않는 경우
* 과거 일을 이번 회차에서 처음 이야기한 경우
* 같은 사실을 더 구체적으로 설명한 경우
* 단어·표현 방식만 달라진 경우
* 실무자가 제안만 하고 대상자의 반응·결정·실행이 없는 경우
* 단순한 감정·의향 표현만 있고 실제 결정이나 행동으로 이어지지 않은 경우
* 중요하지만 변화 없이 유지되는 현재 상태

### 여러 유형이 동시에 해당하는 경우

같은 사건을 중복해서 여러 변화로 만들지 않는다.

가장 구체적으로 진행된 단계 또는 핵심 의미를 가장 잘 설명하는 유형을 우선한다.

예:

* 치료 의사를 밝힘 → `결정 변화`
* 치료 의사를 밝힌 뒤 실제 진료까지 받음 → `실행 진전`

단, `상태 변화`와 `관계 변화`처럼 서로 다른 결과가 각각 상담상 중요하다면 별도로 표시할 수 있다.

## 5\. 회차별 요약과의 관계

구조화된 상담 기록은 사실 확인을 위한 상세 화면이다.

회차별 요약은 이 구조화 기록에서 필요한 사실을 선별해 짧게 보여준다.

`약속 이행 여부`, `상담 중 새로 드러난 것`, `이번 상담 후 새로운 가능성` 분석은 **02 회차별 요약 알고리즘에서 수행**한다.

1\. 약속 이행 여부

3\. 이번 상담 후 새로운 가능성

### \[절대 고정] 하위 항목 번호 부여 규칙

`약속 이행 여부`, `상담 중 새로 드러난 것`, `이번 상담 후 새로운 가능성`은 **내용이 있는 항목만 화면에 표시**한다.

3. `이번 상담 후 새로운 가능성`

`① 이번 상담 후 새로운 가능성`

`② 이번 상담 후 새로운 가능성`

금지:

* `상담 중 새로 드러난 것`을 항상 ②로 고정하는 것

* 변화 전과 변화 후가 **같은 회차 안에서** 확인됨
* 상담상 의미가 있음

단순히 이번 회차에서 처음 알게 된 사실은 실제 변화로 판정하지 않는다.

### 약속 이행 여부

`약속 이행 여부`는 **같은 회차 안에서 약속·과제·실행 계획이 나오고, 같은 회차 안에서 실제 수행 결과까지 확인되는 경우에만** 표시한다.

이 항목에서도 이전 회차를 참조하지 않는다.

#### 판단 방식

현재 회차 안에서 다음 두 요소가 모두 있어야 한다.

1. 약속·과제·실행 계획
2. 같은 회차 안에서 확인된 실제 수행 결과

둘 중 하나라도 없으면 `약속 이행 여부`를 표시하지 않는다.

예를 들어 현재 회차에서 약속만 만들어졌고 실제 수행 결과가 아직 없으면 ①에 넣지 않는다.

#### 화면 표시 형식

가능한 경우 아래 순서를 사용한다.

`약속: "\\\\\\\\\\\\\\\[현재 회차에서 실제로 기록된 약속/과제/실행 계획]"`

`실제 결과: "\\\\\\\\\\\\\\\[같은 회차에서 실제로 확인된 수행 결과]"`

`변화점:`

* `\\\\\\\\\\\\\\\[변화 항목]: \\\\\\\\\\\\\\\[같은 회차 안의 이전 상태] → \\\\\\\\\\\\\\\[같은 회차 안의 이후 상태] (\\\\\\\\\\\\\\\[기록에 있는 의미])`
* `\\\\\\\\\\\\\\\[실행 양상]: "\\\\\\\\\\\\\\\[같은 회차 안의 이전 태도]" → "\\\\\\\\\\\\\\\[같은 회차 안의 현재 행동/태도]"`

`∴ \\\\\\\\\\\\\\\[기록에 근거한 핵심 심리/행동 요약]`

#### 작성 규칙

* `약속`은 현재 회차 수기에 실제로 기록된 약속·과제·실행 계획의 어휘를 그대로 사용한다.
* `실제 결과`도 현재 회차 수기에 실제로 등장한 어휘를 그대로 사용한다.
* `변화점:`은 같은 회차 안에서 변화 전후가 실제로 확인될 때만 표시한다.
* `∴` 문장은 같은 회차 기록에 근거한 내용이 충분할 때만 표시한다.
* `∴`를 만들기 위해 원문에 없는 `불안 극복`, `효능감 증가`, `회복력`, `주도성 향상` 등의 해석어를 새로 만들지 않는다.
* 이전 회차의 과제나 약속을 가져와 `약속`으로 사용하지 않는다.
* 같은 회차 안에서 수행 결과가 확인되지 않으면 `미이행`, `확인되지 않음`처럼 판정하지 말고 ① 자체를 숨긴다.

\---

### 상담 중 새로 드러난 것

상담 중 새로 드러난 것은 같은 회차의 상담 과정에서 처음 확인된 의미 있는 발화·행동·인식·강점·대처 방식 등을 정리한다.



이 항목은 회차별 요약 화면에만 적용되는 예외 영역이다.



같은 회차 안에서 변화 전후가 확인된 내용뿐 아니라, 변화 전후는 확인되지 않았지만 상담의 이해나 후속 진행에 의미 있는 새 정보도 포함할 수 있다.

포함할 수 있는 내용:

* 새롭게 드러난 강점
* 대처 방식
* 자기이해
* 문제 인식
* 선택 기준
* 해결 방향
* 사고방식의 변화
* 상담 중 처음 확인된 의미 있는 행동 또는 표현

#### 화면 표시 형식

실제 직접 발화가 기록에 있는 경우 다음 형식을 사용할 수 있다.

`실무자: "\\\\\\\\\\\\\\\[실무자의 실제 질문이나 촉진 내용]"`

`당사자: "\\\\\\\\\\\\\\\[당사자의 실제 대답이나 깨달음 내용]"`

`변화점:`

* `\\\\\\\\\\\\\\\[당사자의 주도적 변화 서술]`
* `"\\\\\\\\\\\\\\\[같은 회차 안의 앞선 생각/표현]" → "\\\\\\\\\\\\\\\[같은 회차 안의 이후 생각/표현]"`

#### 작성 규칙

* 판단 범위는 현재 회차 안으로 한정한다.
* `실무자:` / `당사자:`는 **실제 기록에 직접 발화가 있을 때만** 사용한다.
* 직접 발화가 없으면 대사를 재구성하거나 만들어내지 않는다.
* 직접 발화가 없더라도 수기 기록에 실제 행동이나 표현이 있으면 그 원문 어휘를 사용해 내용을 표시할 수 있다.
* 변화 전후가 확인된 경우에만 변화점:을 사용한다. 새롭게 확인된 사실만 있는 경우에는 확인된 내용:을 사용한다.
* 예시는 다음처럼 구분하면 됩니다.
* 
* 확인된 내용:
* \- 혼자 일을 정리할 때 사용하는 방식에 대해 이야기함
* 
* 변화가 실제 확인되면:
* 
* 변화점:
* \- "혼자 결정하기 어려움" → "우선순위를 정해서 진행하기로 함"
* 사고·인식 변화의 화살표는 같은 회차 안에서 전후가 실제로 확인될 때만 사용한다.
* 실무자가 해석했을 뿐 당사자의 발화·행동 근거가 없는 내용은 쓰지 않는다.
* 원문에 없는 심리 용어나 전문 용어를 붙이지 않는다.

\---

### 이번 상담 후 새로운 가능성

`이번 상담 후 새로운 가능성`은 **같은 회차 안에서 확인된 변화가 그 회차 후반의 새로운 행동·계획·합의로 실제 이어진 경우에만** 표시한다.

미래를 AI가 전망하는 영역이 아니다.

#### 판단 방식

현재 회차 안에서 다음 흐름이 실제 기록으로 확인되어야 한다.

`이번 회차 안에서 확인된 변화 → 같은 회차 후반의 새로운 행동·계획·합의`

근거로 사용할 수 있는 내용:

* 당사자가 같은 회차 후반에 직접 말한 다음 행동 의지
* 실무자와 같은 회차 안에서 실제로 합의한 다음 행동
* 같은 회차에서 확인된 변화와 연결해 실제로 논의한 새로운 행동
* 같은 회차 말미에 정한 구체적인 수행 과제 또는 계획

#### 화면 표시 형식

실제 직접 발화가 기록에 있는 경우 다음 형식을 사용할 수 있다.

`실무자: "\\\\\\\\\\\\\\\[확장 및 적용을 돕는 실무자의 실제 제안]"`

`당사자: "\\\\\\\\\\\\\\\[당사자의 실제 수용 및 의지 표현]"`

`변화점:`

* `\\\\\\\\\\\\\\\[같은 회차에서 확인된 변화/성공] → \\\\\\\\\\\\\\\[같은 회차 후반에 합의된 새로운 행동·계획]`
* `\\\\\\\\\\\\\\\[같은 회차 안에서 실제 확인된 인식의 연결]`

#### 작성 규칙

* 판단 범위는 현재 회차 안으로 한정한다.
* 실제 기록된 발화가 없으면 실무자/당사자 대사를 만들지 않는다.
* 직접 발화가 없으면 실제 합의·과제·계획의 원문 어휘로만 정리한다.
* 변화에서 다음 행동으로의 연결이 같은 회차 안에서 실제로 확인될 때만 화살표 형식을 사용한다.
* `작은 성공 → 효능감 증대`처럼 기록에 없는 심리적 일반화를 만들지 않는다.
* 기록에 없는 가능성을 AI가 전망하지 않는다.
* 다음 회차 기록을 가져와 가능성이 실제 실현되었는지 확인하거나 보강하지 않는다.

\---

### 중복 처리

같은 사실이 세 하위 항목 여러 곳에 걸칠 수 있다.

화면에서는 동일 문장을 반복하지 않는다.

* 같은 회차 안의 약속과 실제 수행 결과가 핵심이면 `약속 이행 여부`에 둔다.
* 상담 과정에서 새롭게 나온 발화·행동·인식이 핵심이면 `상담 중 새로 드러난 것`에 둔다.
* 같은 회차 안에서 확인된 변화가 그 회차 후반의 새로운 행동·계획·합의로 이어진 것이 핵심이면 `이번 상담 후 새로운 가능성`에 둔다.

내용이 겹치면 가장 정보 가치가 높은 위치에 한 번만 보여준다.

## 8\. 문장 작성 규칙

### 8-1. 원문 어휘 고정 규칙

회차별 요약은 내용을 짧게 선별할 수는 있지만, **원문에 있는 핵심 어휘를 다른 말로 바꾸어 요약하지 않는다.**

* 상담 사실을 다시 쓰는 문장의 핵심 명사·동사·형용사는 **수기 기록에 실제로 등장한 어휘를 우선 그대로 사용**한다.
* 원문에 있는 단어를 더 자연스럽거나 전문적으로 보이게 하려고 동의어·유사어·상위 개념·전문 용어로 치환하지 않는다.
* 원문이 `노력했다`라고 쓰면 `시도했다`로 바꾸지 않는다.
* 원문이 `상담했다`라고 쓰면 원문에 없는 `멘토링했다`로 바꾸지 않는다.
* 원문이 `이야기함`, `말함`, `약속함`, `참여함`, `신청함`, `등록함`, `동행함`, `확인함` 등으로 기록되어 있으면 가능한 한 그 단어를 그대로 유지한다.
* 원문에 없는 `회복력`, `효능감`, `역량 강화`, `멘토링`, `개입 성과` 등의 해석·전문 표현을 임의로 덧붙이지 않는다. 단, 해당 단어가 실제 수기 기록에 있으면 사용할 수 있다.
* 문장을 짧게 만들 때는 **원문에서 덜 중요한 부분을 생략하는 방식으로 축약**하고, 남은 내용을 다른 표현으로 재작성하지 않는다.
* 문장 연결에 필요한 조사·어미·접속어는 최소한으로 조정할 수 있으나, 사건·행동·상태를 나타내는 핵심 단어는 바꾸지 않는다.
* 여러 원문 문장을 한 문장으로 합칠 때도 원문에 없는 동사나 평가어를 새로 만들어 연결하지 않는다.
* 사실 확정 기준은 수기 기록이므로, 수기와 녹음 전사에서 표현이 다를 경우 회차별 요약에는 수기 기록의 어휘를 우선한다.

### 8-2. 기본 문장 규칙

* 한 문장에 한 핵심 사실을 우선한다.
* 원문의 표현과 어휘를 최대한 그대로 유지한다.
* 원문에 없는 단어나 임의 해석을 추가하지 않는다.
* 사실과 분석을 구분한다.
* 긴 줄글을 지양한다.
* 건수 중심 요약을 지양한다.
* 같은 사실을 반복하지 않는다.
* 당사자의 감정, 의도, 동기, 진단을 기록 없이 추정하지 않는다.
* 직접 발화는 실제 기록에 존재하는 경우에만 인용하고, 인용문 안의 단어를 고쳐 쓰지 않는다.

## 목적

회차별 요약 화면에서 `녹음 전사 보기`를 눌렀을 때 제공되는 화면의 규칙을 정의한다.

자동 전사본을 누락 없이 전체 보여주고, 그 안에서 수기 기록과 사실이 다른 부분과 주요 내용을 표시한다.

## 화면 구성

녹음 전사 데이터가 존재하는 경우 자동 전사된 문장을 시간순으로 나열한다.

클로바노트 형태의 타임라인을 권장한다.

전사 위에는 다음 두 종류의 표시를 사용할 수 있다.

### 1\. 기록 불일치 표시

* 판정 기준은 `별첨\\\\\\\_기록불일치\\\\\\\_처리규칙.md`를 따른다.
* 4대 조건을 모두 만족하는 경우에만 `수기 기록과 다름`으로 표시한다.
* 해당 문장의 배경을 형광펜 스타일로 강조할 수 있다.
* 문장을 누르면 화면 우측, 모바일에서는 하단에 대조 패널을 연다.

대조 패널에는 아래 4개 항목만 표시한다.

1. 차이점
2. 녹음 전사 내용
3. 수기 기록 내용
4. 연결된 수기 단락

4대 조건 분석표 자체는 사용자 화면에 노출하지 않는다.

### 2\. 주요 내용 표시

왼쪽 색 띠 또는 간단한 상태 뱃지로 표시한다.

* 🔵 이번 회차에서 확인된 변화
* 🟠 확인필요
* 🟢 완료·해결

회차별 요약의 하위 항목 명칭은 녹음 전사 화면의 기본 분류로 사용하지 않는다.



녹음 전사 화면은 구조화된 상담 기록에서 판정된 🔵·🟠·🟢 상태와 기록 불일치만 표시한다.



표시기준

### 🔵 이번 회차에서 확인된 변화

녹음 전사 화면의 🔵 표시는 01 구조화된 상담 기록 알고리즘에서 실제 변화로 판정된 내용을 연결하여 표시한다.



02 회차별 요약 알고리즘의 상담 중 새로 드러난 것에만 적용되는 예외 내용은, 01의 변화 조건을 충족하지 않는 한 녹음 전사 화면에서 🔵로 표시하지 않는다.

녹음 전사 내용만으로 새로운 변화를 생성하지 않는다.

`🔵 이번 회차에서 확인된 변화`는 **해당 회차 내부의 수기 기록만 기준으로 판정**한다.

* 이전 회차의 상담 내용, 과제, 약속, 계획, 상태를 가져와 비교하지 않는다.
* `약속 이행 여부`는 같은 회차 안에서 약속·과제·실행 계획과 실제 수행 결과가 모두 확인될 때만 연결한다.
* 상담 중 새로 드러난 것 중 같은 회차 안에서 실제 변화 전후가 확인된 내용만 녹음 전사 화면의 🔵 표시와 연결할 수 있다.
* 
* 변화 전후 없이 회차별 요약의 예외 규칙으로만 표시된 내용은 녹음 전사 화면에서 🔵로 표시하지 않는다. 필요한 경우 색상 없는 일반 연결 정보로만 제공할 수 있다.



* `이번 상담 후 새로운 가능성`은 같은 회차 안에서 확인된 변화가 그 회차 후반의 새로운 행동·계획·합의로 이어진 경우만 연결한다.

`약속 이행 여부`, `상담 중 새로 드러난 것`, `이번 상담 후 새로운 가능성`은 02 규칙에서 수기 기록을 근거로 판정하며, 전사 화면은 해당 내용을 보조적으로 연결할 수 있을 뿐 독립적으로 새 분석을 만들지 않는다.

02 규칙의 하위 분석 명칭을 화면에 함께 보여주는 경우에는 다음 의미 순서를 따른다.

* `약속 이행 여부`
* `상담 중 새로 드러난 것`
* `이번 상담 후 새로운 가능성`

다만 앞의 숫자는 각 항목에 고정하지 않는다. 내용이 있는 항목만 남긴 뒤 실제 표시 순서에 따라 `①`부터 연속 부여한다.

예:

* `상담 중 새로 드러난 것`만 있으면 `① 상담 중 새로 드러난 것`
* `상담 중 새로 드러난 것`과 `이번 상담 후 새로운 가능성`만 있으면 `① 상담 중 새로 드러난 것`, `② 이번 상담 후 새로운 가능성`

`A. 이번 회차 안에서 확인된 변화`, `B.`, `C.`, `D.` 구조는 사용하지 않는다.

`행동 변화`, `태도 변화`, `상태 변화`, `결정 변화`, `실행 진전`, `관계 변화`는 내부 판정용이며 화면 소제목이나 보조 라벨로 만들지 않는다.

#### 상단 헤더

* `릴레이어` 로고 배지
* `사회연대은행` 태그

#### 당사자 식별 카드

* 제공된 상담 데이터에 **명시적으로 존재하는 사실만 표시**.
* 기록에 없는 나이, 거주지, 직업, 가족관계, 소득, 진단, 지역명 등을 추정하거나 생성하지 말 것.

* 신청서가 있으면 실제 내용만 요약.

`첨부된 신청서 파일이 없습니다`

#### 첫상담 기록

* 화면에서 기존 `인테이크` 명칭을 사용하지 않고 반드시 `첫상담 기록`으로 통일.

* 수기 원문의 표현, 어휘, 오탈자, 줄바꿈을 임의로 정제하거나 재작성하지 말 것.

## 3\. 회차 목록 및 AI 회차별 요약

### 회차 정렬

* 실제 존재하는 모든 상담 회차를 **최신 회차 → 가장 오래된 회차 순으로 역순 정렬**.
* 존재하지 않는 회차는 만들지 말 것.

### 각 회차 헤더

한 줄 안에 다음 정보를 표시한다.

* 회차 번호
* 상담 일시
* 해당 회차 상담 목표
* `\\\\\\\[녹음 전사 보기]`
* `\\\\\\\[상담 기록 보기]`

상담 목표가 기록에 없으면 임의로 생성하지 말 것.

### AI 회차별 요약

각 회차 카드 본문에 `AI 회차별 요약` 영역을 둔다.

최상위 요약 영역은 반드시 아래 순서만 사용한다.

1. `이번 상담의 핵심`
2. `🔵 이번 회차에서 확인된 변화`
3. `🟠 확인필요`
4. `🟢 완료·해결`

내용이 없는 항목은 숨긴다.

`긴급·위험` 등 별도의 최상위 카테고리를 임의로 추가하지 않는다.

## 4\. 🔵 이번 회차에서 확인된 변화

`02 회차별 요약 알고리즘`을 따른다.

### \[절대 고정] 회차 범위

`🔵 이번 회차에서 확인된 변화`는 **오직 현재 회차 내부만 분석한다.**

* 이전 회차의 상담 내용, 과제, 약속, 계획, 상태를 가져와 비교하지 않는다.
* 현재 회차에서 처음 나온 사실을 이전 회차와 연결해 변화로 만들지 않는다.
* 다음 회차의 결과를 가져와 현재 회차의 변화나 가능성을 보강하지 않는다.
* 모든 변화 전후는 같은 회차 안에서 실제로 확인되어야 한다.

### \[절대 고정] 화면 구조

`🔵 이번 회차에서 확인된 변화`에서 사용할 수 있는 하위 항목의 의미 순서는 아래와 같다.

1. `약속 이행 여부`
2. `상담 중 새로 드러난 것`
3. `이번 상담 후 새로운 가능성`

하지만 화면의 `① ② ③`은 각 의미 항목에 고정된 번호가 아니다.



사용자 화면에서는 아래 3개의 고정 소제목만 사용한다.



1\. 약속 이행 여부

2\. 상담 중 새로 드러난 것

3\. 이번 상담 후 새로운 가능성



다른 소제목은 절대 생성하지 않는다.



행동 변화, 태도 변화, 상태 변화, 결정 변화, 실행 진전, 관계 변화,

강점, 문제 인식, 선택 기준, 해결 방향 등은 내부 판정 기준으로만 사용하고

사용자 화면의 제목으로 노출하지 않는다.



### \[절대 고정] 하위 항목 번호 부여 규칙

`약속 이행 여부`, `상담 중 새로 드러난 것`, `이번 상담 후 새로운 가능성`은 **내용이 있는 항목만 화면에 표시**한다.

앞의 숫자 `① ② ③`은 각 항목에 고정된 번호가 아니다.

숫자는 **실제로 화면에 표시되는 항목의 순서에 따라 ①부터 다시 연속 부여**한다.

기본 의미 순서는 다음과 같다.

1. `약속 이행 여부`
2. `상담 중 새로 드러난 것`
3. `이번 상담 후 새로운 가능성`

단, 내용이 없는 항목은 숨기고 번호도 차지하지 않는다.

예시:

* 세 항목이 모두 있으면  
`약속 이행 여부`  
`상담 중 새로 드러난 것`  
`이번 상담 후 새로운 가능성`
* `상담 중 새로 드러난 것`만 있으면  
`① 상담 중 새로 드러난 것`
* `이번 상담 후 새로운 가능성`만 있으면  
`① 이번 상담 후 새로운 가능성`
* `약속 이행 여부`와 `이번 상담 후 새로운 가능성`만 있으면  
`약속 이행 여부`  
`② 이번 상담 후 새로운 가능성`
* `상담 중 새로 드러난 것`과 `이번 상담 후 새로운 가능성`만 있으면  
`① 상담 중 새로 드러난 것`  
`② 이번 상담 후 새로운 가능성`

금지:

* `약속 이행 여부`를 항상 ①로 고정하는 것
* `상담 중 새로 드러난 것`을 항상 ②로 고정하는 것
* `이번 상담 후 새로운 가능성`을 항상 ③으로 고정하는 것
* 앞 항목이 숨겨졌는데도 `②`, `③`부터 시작하는 것
* 번호가 `① → ③`처럼 건너뛰는 것



다음은 금지한다.

* `A. 이번 회차 안에서 확인된 변화`
* `B. 약속 이행 여부`
* `C. 상담 중 새로 드러난 강점·통찰`
* `D. 다음 행동으로 이어질 가능성`
* `이번 회차 안에서 확인된 변화 · 결정 변화`
* `상태/태도 변화`
* 변화 유형을 붙여 만든 임의의 소제목·뱃지·라벨

`행동 변화`, `태도 변화`, `상태 변화`, `결정 변화`, `실행 진전`, `관계 변화`는 내부 판정용으로만 사용하고 화면에 노출하지 않는다.

### 약속 이행 여부

**같은 회차 안에서 약속·과제·실행 계획이 나오고, 그 회차 안에서 실제 수행 결과까지 확인되는 경우에만 표시한다.**

이전 회차의 약속이나 과제를 가져오지 않는다.

현재 회차에서 약속만 생기고 실제 수행 결과가 아직 없으면 ①을 표시하지 않는다.

가능한 경우 아래 형식을 사용한다.

`약속: "\\\\\\\[현재 회차에서 실제로 기록된 약속/과제/실행 계획]"`

`실제 결과: "\\\\\\\[같은 회차에서 실제로 확인된 수행 결과]"`

`변화점:`

* `\\\\\\\[변화 항목]: \\\\\\\[같은 회차 안의 이전 상태] → \\\\\\\[같은 회차 안의 이후 상태] (\\\\\\\[기록에 있는 의미])`
* `\\\\\\\[실행 양상]: "\\\\\\\[같은 회차 안의 이전 태도]" → "\\\\\\\[같은 회차 안의 현재 행동/태도]"`

`∴ \\\\\\\[기록에 근거한 핵심 심리/행동 요약]`

규칙:

* `약속`과 `실제 결과`는 현재 회차 수기에 실제로 등장한 어휘를 그대로 사용한다.
* `변화점:`은 같은 회차 안에서 변화 전후가 실제로 확인될 때만 쓴다.
* `∴` 문장은 같은 회차 기록에 근거가 충분할 때만 쓴다.
* 같은 회차 안에 실제 수행 결과가 없으면 `미이행`, `확인되지 않음`이라고 만들지 말고 ① 전체를 숨긴다.

### 상담 중 새로 드러난 것

**같은 회차의 상담 과정에서 새롭게 나온 발화·행동·인식 등을 확인한다.**

실제 직접 발화가 기록에 있을 때만 다음 형식을 사용할 수 있다.

`실무자: "\\\\\\\[실무자의 실제 질문이나 촉진 내용]"`

`당사자: "\\\\\\\[당사자의 실제 대답이나 깨달음 내용]"`

실제 변화 전후가 확인된 경우:

변화점:

\- \[같은 회차 안의 전후 내용]



변화 전후 없이 새롭게 확인된 내용인 경우:

확인된 내용:

\- \[수기 기록에서 처음 확인된 의미 있는 내용]규칙:

* 판단 범위는 현재 회차 안으로 한정한다.
* 실무자/당사자 대사를 재구성하거나 창작하지 않는다.
* 직접 발화가 없으면 대사 줄은 생략하고 실제 수기 기록에 있는 행동·표현만 사용한다.
* 화살표는 같은 회차 안에서 실제 전후가 확인될 때만 사용한다.
* 원문에 없는 `통찰`, `회복력`, `효능감`, `역량 강화` 등의 해석어를 새로 붙이지 않는다.

### 이번 상담 후 새로운 가능성

**같은 회차 안에서 확인된 변화가 그 회차 후반의 새로운 행동·계획·합의로 이어진 경우만 표시한다.**

이 영역은 AI의 미래 전망이 아니다.

현재 회차 안에서 다음 흐름이 실제 기록으로 확인되어야 한다.

`이번 회차 안에서 확인된 변화 → 같은 회차 후반의 새로운 행동·계획·합의`

실제 직접 발화가 기록에 있을 때만 다음 형식을 사용할 수 있다.

`실무자: "\\\\\\\[확장 및 적용을 돕는 실무자의 실제 제안]"`

`당사자: "\\\\\\\[당사자의 실제 수용 및 의지 표현]"`

`변화점:`

* `\\\\\\\[같은 회차에서 확인된 변화/성공] → \\\\\\\[같은 회차 후반에 합의된 새로운 행동·계획]`
* `\\\\\\\[같은 회차 안에서 실제 확인된 인식의 연결]`

규칙:

* 판단 범위는 현재 회차 안으로 한정한다.
* 실제 기록된 발화가 없으면 실무자/당사자 대사를 만들지 않는다.
* 직접 발화가 없으면 실제 합의·과제·계획의 원문 어휘로만 정리한다.
* 변화에서 새로운 행동·계획으로의 연결이 같은 회차 안에서 확인될 때만 화살표를 사용한다.
* 다음 회차의 실제 수행 결과를 가져와 현재 회차의 가능성을 보강하지 않는다.
* 기록에 없는 가능성을 AI가 전망하지 않는다.

### 중복 처리

세 하위 항목에 같은 사실이 반복될 경우 동일 문장을 여러 번 출력하지 않는다.

* 같은 회차 안의 약속과 실제 수행 결과가 핵심이면 `약속 이행 여부`에 둔다.
* 같은 회차의 상담 과정에서 새롭게 나온 발화·행동·인식이 핵심이면 `상담 중 새로 드러난 것`에 둔다.
* 같은 회차 안의 변화가 그 회차 후반의 새로운 행동·계획·합의로 이어진 것이 핵심이면 `이번 상담 후 새로운 가능성`에 둔다.



단, 상담 중 새로 드러난 것은 회차별 요약 영역에만 적용되는 예외 항목이다.



같은 회차의 상담 과정에서 처음 확인된 의미 있는 발화·행동·인식은 변화 전후가 확인되지 않더라도 이 항목에 표시할 수 있다.



이 예외는 상담 기록 보기의 🔵 표시와 녹음 전사 보기의 🔵 하이라이트에는 적용하지 않는다.

## 5\. 상담 기록 보기 모달

`01 구조화된 상담기록 알고리즘`을 따른다.

### 구조

`큰 주제(01, 02...) → 세부 단락(1-1, 1-2...) → 수기 기록 원문`의 3단계 계층형 아코디언.

### 원문 보존

* 수기 기록의 어휘, 오탈자, 문장, 줄바꿈을 가능한 한 글자 하나 바꾸지 않고 보존.
* 문법 교정, 표현 순화, 임의 재작성 금지.
* 원문에 없는 배경 설명 추가 금지.

### 중요 의미 표시

중요한 문장에만 제한적으로 표시한다.

* `🔵 이번 회차에서 확인된 변화`
* `🟠 확인필요`
* `🟢 완료·해결`

모든 문장에 상태 표시를 붙이지 않는다.



회차별 요약의 상담 중 새로 드러난 것에 표시된 내용이라도, 01의 변화 조건을 충족하지 않으면 상담 기록 원문에 🔵 표시를 붙이지 않는다.

## 6\. 녹음 전사 보기 모달

`04 녹음 전사 하이라이트·연결 규칙` 및 `별첨 기록 불일치 처리 규칙`을 따른다.

### 녹음 전사 데이터가 있는 경우

2단 Split View로 구성한다.

#### 상단 필수 경고문

`자동 전사본이라 틀린 부분이 있을 수 있습니다.`

#### 좌측 패널

클로바노트 형태의 시간순 타임라인으로 해당 회차 녹음 전사 전문을 누락 없이 전체 렌더링한다.

전사 내용을 임의로 요약하거나 일부만 표시하지 않는다.

#### 우측 대조 패널

기록 불일치 문장을 선택했을 때 아래 4개 항목만 표시한다.

* `차이점`
* `녹음 내용`
* `수기 내용`
* `연결된 수기 단락`

다음 내부 표현은 사용자 화면에 노출하지 않는다.

* 4대 조건 분석표
* 색 A / 색 B
* 내부 판정 점수
* 모델 추론 과정

#### 하단 필터

`기록 불일치 모아보기` 버튼 제공.

### 녹음 전사 데이터가 없는 경우

녹음 내용을 임의로 생성하지 않는다.

`녹음 전사 보기`를 열면 다음 빈 상태를 표시한다.

`첨부된 녹음 전사본이 없습니다`

가상의 발화, 시간 코드, 화자, 불일치 항목을 생성하지 않는다.



회차별 요약 전용 예외로 상담 중 새로 드러난 것에 포함된 내용은, 01의 변화 조건을 충족하지 않는 한 녹음 전사 화면에서 🔵로 하이라이트하지 않는다.

## \[엄격 준수] 업무 및 데이터 처리 규칙

### 1\. 무왜곡·무창작 원칙

* 수기 기록와 녹음 전사에 등장하지 않는 사실을 절대 창작하지 말 것.
* 나이, 거주지, 지역, 직업, 질병, 진단, 가족관계, 경제 상태, 일정, 행동 패턴 등을 임의로 추정하지 말 것.
* 사실로 확정하여 표시하는 `AI 회차별 요약`과 `상담 기록 상세`는 **실무자의 수기 기록를 기준**으로 한다.
* 녹음 전사는 보조 자료로만 사용한다.
* 녹음 내용만을 근거로 수기 기록에 없는 새로운 사실을 확정하지 않는다.
* 당사자의 감정, 의도, 동기, 효능감, 회복 가능성 등을 기록 없이 추정하지 않는다.

### 2\. 전체 페이지 원문 어휘 고정 규칙

이 규칙은 `이번 상담의 핵심`, `🔵 이번 회차에서 확인된 변화`의 세 하위 항목 내용, `🟠 확인필요`, `🟢 완료·해결`, 큰 주제/세부 단락 제목, 상담 기록 상세의 생성 설명, 녹음 전사 대조 패널의 `차이점` 등 **상담 사실을 다시 표현하는 모든 생성 문구**에 적용한다. UI 자체의 고정 버튼명·고정 카테고리명은 예외다.

* 상담 사실을 표현하는 핵심 명사·동사·형용사는 **수기 기록 또는 해당 원문에 실제 등장한 어휘를 그대로 사용**한다.
* 원문을 더 자연스럽게, 전문적으로, 짧게 보이게 한다는 이유로 동의어·유사어·상위 개념·전문 용어로 바꾸지 말 것.
* 원문이 `노력했어요/노력함`이면 `시도했어요/시도함`으로 바꾸지 말 것.
* 원문이 `상담했어요/상담함`이면 원문에 없는 `멘토링했어요/멘토링함`으로 바꾸지 말 것.
* 원문이 `이야기함`, `말함`, `약속함`, `참여함`, `신청함`, `등록함`, `동행함`, `확인함` 등으로 기록되어 있으면 가능한 한 해당 단어를 그대로 사용할 것.
* 원문에 없는 `회복력`, `효능감`, `역량 강화`, `멘토링`, `개입 성과` 같은 해석·전문 표현을 새로 붙이지 말 것. 단, 실제 원문에 그 단어가 있으면 사용할 수 있다.
* 내용을 줄여야 할 때는 **원문에서 일부를 생략하는 방식으로 축약**하고, 남은 내용을 다른 단어로 치환하여 재작성하지 말 것.
* 문법상 연결을 위해 필요한 조사·어미·접속어는 최소한으로 조정할 수 있으나, 사건·행동·상태를 나타내는 핵심 어휘는 바꾸지 말 것.
* 여러 원문 문장을 합칠 때도 원문에 없는 동사나 평가어를 새로 만들어 연결하지 말 것.
* 사실로 확정하는 요약은 수기 기록을 기준으로 하므로, 수기와 녹음 전사의 표현이 다르면 수기 기록의 어휘를 우선할 것.
* 직접 발화는 실제 기록된 문장을 그대로 인용하고 인용문 안의 단어·어미를 고쳐 쓰지 말 것.

### 3\. 요약 작성 규칙

* 한 문장에 한 핵심 사실을 우선한다.
* 수기 원문의 표현과 어휘를 최대한 그대로 유지한다.
* 기록에 없는 해석을 추가하지 않는다.
* 중복 사실을 반복하지 않는다.
* 단순 건수 나열식 요약을 지양한다.
* 중요한 현재 상태, 변화, 결정, 후속 행동, 약속 이행 결과, 강점·통찰, 완료 사항을 중심으로 선별한다.

### 4\. 기록 불일치 판정 규칙

녹음 전사와 수기 기록이 모두 존재하는 경우에만 기록 불일치를 판정한다.

다음 4개 조건을 모두 만족할 때만 불일치로 표시한다.

1. 동일 대상
2. 동일 속성 또는 동일 사건
3. 동일 시기 또는 동일 사건 범위
4. 두 내용이 동시에 참이기 어려운 양립 불가 관계

다음은 불일치로 처리하지 않는다.

* 수기에 녹음 내용 일부가 생략된 경우
* 단순 어휘 차이
* 표현 방식 차이
* 한쪽 기록이 더 구체적인 경우
* 같은 사실을 다른 문맥에서 설명한 경우

불일치가 확인되더라도 어느 한쪽을 자동으로 오류라고 단정하지 않는다.
확인되지 않은 불일치 내용은 회차별 요약이나 상담 기록에 확정 사실로 기재하지 않는다.

## 데이터 적용 원칙

* 제공된 상담 데이터에 실제 존재하는 회차만 생성한다.
* 회차 수를 임의로 제한하거나 추가하지 않는다.
* 특정 사례에만 존재하는 인명, 기관명, 사건, 시간 코드, 프로젝트명 등을 공통 규칙으로 가정하지 않는다.
* 예시 데이터를 실제 상담 데이터처럼 출력하지 않는다.
* 입력 자료에 없는 정보는 빈 상태 또는 `기록 없음`으로 처리하고 창작하지 않는다.

## 출력 전 필수 자체 점검

HTML을 출력하기 직전에 다음 항목을 반드시 다시 확인한다.

1. `🔵 이번 회차에서 확인된 변화`를 만들 때 이전 회차의 상담 내용·과제·약속·계획·상태를 참조하지 않았는가.
2. `약속 이행 여부`의 약속과 실제 결과가 모두 같은 회차 안에서 확인되는가.
3. 같은 회차 안의 실제 수행 결과가 없는데 `미이행`, `확인되지 않음` 등을 임의로 만들지 않았는가.
4. 상담 중 새로 드러난 것이 같은 회차의 수기 기록에 있는 실제 발화·행동·인식에 근거하는가.
5. `이번 상담 후 새로운 가능성`이 같은 회차 안의 변화에서 같은 회차 후반의 행동·계획·합의로 실제 이어지는가.
6. 다음 회차 결과를 가져와 현재 회차의 변화나 가능성을 보강하지 않았는가.
7. 세 의미 항목 중 내용이 없는 항목을 숨겼는가.
8. 남은 하위 항목의 화면 번호를 실제 표시 순서대로 `①`부터 연속 부여했는가.
9. `상담 중 새로 드러난 것` 하나만 있을 때 `① 상담 중 새로 드러난 것`으로 표시되는가.
10. `이번 상담 후 새로운 가능성` 하나만 있을 때 `① 이번 상담 후 새로운 가능성`으로 표시되는가.
11. 두 항목만 표시될 때 번호가 반드시 `①`, `②`로 이어지는가.
12. 의미 항목에 `①=약속`, `②=새로 드러난 것`, `③=새로운 가능성`처럼 고정 번호를 부여하지 않았는가.
13. `A. 이번 회차 안에서 확인된 변화`, `B.`, `C.`, `D.` 구조가 화면에 남아 있지 않은가.
14. 6가지 변화 유형이 화면 소제목·뱃지·라벨로 노출되지 않았는가.
15. 수기의 `노력`을 `시도`로, `상담`을 `멘토링`으로 바꾸는 등 원문 어휘를 동의어로 치환한 문장이 없는가.
16. `약속`, `실제 결과`, `실무자`, `당사자`, `변화점`, `∴`에 들어간 핵심 단어가 실제 현재 회차 수기/녹음전사에 존재하는가.
17. 직접 발화가 없는 곳에 `실무자:` / `당사자:` 대사를 만들어 넣지 않았는가.
18. 원문에 없는 전문 용어·심리 해석·감정·동기·평가를 추가하지 않았는가.
19. 수기 원문과 녹음 전사 원문 자체를 수정·정제·축약하지 않았는가.
20. 변화 전후가 없는 상담 중 새로 드러난 것에 변화점:이라는 표현을 사용하지 않았는가.
21. 변화 전후가 없는 경우 확인된 내용:으로 표시했는가.
22. 회차별 요약 전용 예외 내용을 상담 기록에 🔵로 표시하지 않았는가.
23. 회차별 요약 전용 예외 내용을 녹음 전사 화면에 🔵로 표시하지 않았는가.
24. 회차별 요약에 표시되었다는 이유만으로 실제 변화라고 판정하지 않았는가.

위 항목 중 하나라도 위반되면 HTML을 출력하기 전에 수정한다.

## 출력 요구사항

* 생략 없는 완전한 single-file HTML 코드로 출력할 것.
* 반드시 `<!DOCTYPE html>`부터 시작할 것.
* HTML, CSS, JavaScript를 하나의 파일 안에 포함할 것.
* 줄임표 `...`를 사용하여 코드 또는 데이터를 생략하지 말 것.
* 제공된 모든 상담 회차 데이터를 빠짐없이 반영할 것.
* 제공된 수기 기록 원문을 화면에 표시할 때 임의로 축약하지 말 것.
