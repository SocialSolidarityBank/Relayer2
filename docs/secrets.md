# 비밀값과 환경 변수

이 문서는 릴레이어를 다른 기관 환경에 설치하는 운영자를 위한 공개 안내다. 비밀값 자체는
문서·채팅·저장소·로그에 남기지 않는다. 이 문서에는 환경 변수 이름과 의미만 적는다.

## 필수 환경 변수

| 이름 | 의미 | 필수 여부 |
|---|---|---|
| `DATABASE_URL` | 애플리케이션이 사용할 PostgreSQL 연결 문자열 | 필수 |
| `PII_ENC_KEY` | 이름·연락처와 자유 글을 암호화하는 키. base64로 인코딩한 32바이트 키 | 필수 |
| `SESSION_SECRET` | 로그인 세션 쿠키 서명에 사용할 무작위 비밀값 | 필수 |

세 값 중 하나라도 빠지거나 잘못되면 애플리케이션을 시작하지 않거나 로그인·암복호화가
실패한다. `PII_ENC_KEY`를 바꾸면 기존 암호문을 복호화할 수 없으므로 백업·복구 절차와
함께 계획한다.

## 선택 환경 변수

| 이름 | 의미 | 기본 동작 또는 조건 |
|---|---|---|
| `OPENAI_API_KEY` | OpenAI API 인증 키 | 없으면 AI 정리 기능만 사용할 수 없음 |
| `GEMINI_API_KEY` | Google Gemini API 인증 키 | `AI_PROVIDER=gemini`일 때 필요 |
| `AI_PROVIDER` | 사용할 AI 제공자 (`openai` 또는 `gemini`) | 기본값은 `openai` |
| `AI_MODEL` | 제공자별 모델 이름 | 비워 두면 애플리케이션 기본값 사용 |
| `AZURE_SPEECH_KEY` | Azure Speech 인증 키 | 음성 전사를 켤 때 필요 |
| `AZURE_SPEECH_REGION` | Azure Speech 리소스 지역 | 엔드포인트를 직접 지정하지 않을 때 필요 |
| `AZURE_SPEECH_ENDPOINT` | Azure Speech 리소스 전용 HTTPS 엔드포인트 | 지역 대신 사용할 수 있음 |
| `VOICE_ENABLED` | 음성 업로드·전사 기능을 켜는 플래그 | `1`일 때 활성화 |
| `VOICE_ROOT` | 음성 파일을 저장할 디렉터리 | 기본 `./voice`; 배포 교체에도 유지되는 저장소를 사용 |
| `PORT` | HTTP 서버가 수신할 포트 | 기본 `8787` |
| `RELAYER_SLUG` | 기관 배포를 식별하는 읽기 전용 주소 라벨 | 배포 환경에서 선택 |
| `RELAYER_PUBLIC_URL` | 화면에 표시할 공개 접속 주소 | 설정하면 slug보다 우선 |
| `PGSCHEMA` | 사용할 PostgreSQL 스키마 | 지정하지 않으면 기본 스키마 |
| `DOC_ROOT` | 서면 문서 저장 디렉터리 | 기본 `./documents` |
| `STT_CONCURRENCY` | 동시에 처리할 전사 작업 수 | 기본 `2` |

AI와 음성 관련 변수는 기능을 사용하지 않으면 생략할 수 있다. 음성을 사용하려면
`VOICE_ENABLED=1`, `AZURE_SPEECH_KEY`, 그리고 `AZURE_SPEECH_REGION` 또는
`AZURE_SPEECH_ENDPOINT`가 모두 준비되어야 한다.

## 안전한 생성과 보관

신뢰할 수 있는 운영자 장비나 비밀 관리 시스템에서 충분히 긴 무작위 값을 생성한다.
예를 들어 키를 생성할 때는 값을 화면·셸 이력·명령행 인자에 노출하지 않는 절차를
사용한다.

```bash
openssl rand -base64 32       # PII_ENC_KEY에 사용할 32바이트 무작위 값
openssl rand -hex 32          # SESSION_SECRET에 사용할 무작위 값
```

출력값은 즉시 비밀 관리 시스템에 넣고 터미널·클립보드·임시 파일에서 제거한다. 로컬
환경 파일을 쓸 때는 저장소 바깥에 두고 권한을 소유자만 읽을 수 있게 한다(예: `0600`).
`.env`와 백업본을 커밋하거나 공개 로그·스크린샷에 포함하지 않는다.

## 비밀 관리 시스템 사용

[Infisical](https://infisical.com/)은 지원되는 비밀 관리 시스템 중 하나다. 조직이 이미
사용하는 다른 시스템도 다음 조건을 만족하면 사용할 수 있다.

1. 운영 환경별로 별도의 프로젝트·환경·경로를 만들고 접근 권한을 최소화한다.
2. 위 환경 변수 이름을 정확히 저장하거나, 주입 단계에서 애플리케이션 이름으로
   매핑한다.
3. 배포 시 비밀값을 명령행 인자에 넣지 말고 권한이 제한된 환경 파일 또는 런타임
   환경 변수로 주입한다.
4. 자동화에는 사람의 장기 자격 대신 만료·회전 가능한 워크로드 자격을 사용하고,
   자격 자체도 같은 비밀 관리 시스템에서 보호한다.
5. 애플리케이션이 시작되기 전에 필수 변수의 존재 여부를 값 없이 확인한다.

OpenAI 제공자용 저장 이름을 별도로 매핑해야 하는 배포 도구라면 `OPENAI_API_KEY`로
주입되도록 설정한다. 매핑 이름은 도구 설정에만 두고 실제 키는 출력하지 않는다.

## 회전과 복구

- 외부 제공자 키나 데이터베이스 자격을 회전할 때는 비밀 관리 시스템의 값을 먼저
  갱신하고, 새 값으로 배포한 뒤 이전 자격을 폐기한다.
- `PII_ENC_KEY`와 데이터베이스 백업은 서로 다른 보관 위치에 둔다. 키를 잃으면
  백업이 있어도 암호화된 개인정보를 복구할 수 없다.
- 회전 뒤에는 `/health`와 실제 로그인·암호화된 기록 조회·선택 기능의 상태만 확인한다.
  진단 출력에는 값 대신 성공 여부나 HTTP 상태 코드만 남긴다.
- 상세한 배포·백업·교체 순서는 `docs/ops-internal.md`의 값 없는 절차를 참고한다.
